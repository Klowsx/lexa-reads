# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

**Lexa Reads** — a social book-tracking mobile app (Letterboxd for books), React Native + Expo, Supabase backend. Full product spec, DB schema, and architecture decisions live in `STACK.md` — treat it as the canonical reference. The MVP is built and wired to Supabase (feed, library, book, lists, user, auth, notifications, comments); remaining work is hardening, accessibility and store-readiness (see `docs/auditoria.md`).

## Commands

**Package manager: `pnpm` only.** `npm` and `yarn` are blocked — `package.json` has a `preinstall` hook that aborts if another package manager is used, and `packageManager` is pinned to `pnpm@10.33.2`.

All commands run from the repo root:

```bash
pnpm start         # Expo dev server
pnpm android       # Android emulator/device
pnpm ios           # iOS simulator
pnpm web           # Browser

# Regenerate Supabase TypeScript types when schema changes
supabase gen types typescript --project-id <id> > src/types/database.ts

# Type-check without emitting
pnpm tsc --noEmit
```

**Environment variables** go in `.env.local` (gitignored):

```
EXPO_PUBLIC_SUPABASE_URL=
EXPO_PUBLIC_SUPABASE_ANON_KEY=
```

## Architectural rules (enforce always)

1. **`app/` is routes only.** Logic lives in `src/`. Screens import from `src/`; `src/` never imports from `app/`.

2. **Data flow:** Screen → `src/features/*/hooks/` (TanStack Query) → `src/lib/supabase.ts` → Supabase.

3. **Server state = TanStack Query. Client state = Zustand** (only auth session + toast queue). Never use Zustand for server data.

4. **`google-books.ts` is the only place to call the Google Books API.** Always query the local `books` table first by `google_books_id`; if missing, fetch → insert → return. Screens never hit the external API directly.

5. **`queryOptions` factory pattern** — no loose query keys:

   ```ts
   export const feedQueryOptions = (cursor?: string) =>
     queryOptions({
       queryKey: ['feed', cursor],
       queryFn: () => fetchFeed(cursor)
     })
   ```

6. **Infinite scroll with cursor, not offset** — cursor = `(created_at, id)`.

7. **`focusManager.setFocused` wired to `AppState`** in root `_layout.tsx` so TanStack Query refetches on app foreground.

8. **Mutations use optimistic updates** (`onMutate` snapshot → `onError` revert → `onSettled` invalidate) for likes and status changes.

9. **No `try/catch` in screens.** `QueryClient.defaultOptions.mutations.onError` dispatches toasts globally.

10. **Auth tokens in `expo-secure-store`**, never `AsyncStorage`.

11. **Never update denormalized counters manually.** They are maintained by DB triggers (`followers_count`, `books_read_count`, `likes_count`, `comments_count`).

12. **RLS policies are written as SQL in migrations**, not described in prose. All tables have RLS enabled.

13. **Simplicidad antes que capas adicionales.** Seguir las reglas de `AGENTS.md`: no crear reexports internos ni wrappers triviales de un solo uso, ni mover código únicamente para acortar un archivo. Una extracción debe aportar reutilización real, una responsabilidad clara o cumplir una obligación arquitectónica, como las rutas de Expo Router.

## Key UI patterns

**`QueryBoundary`** — standard wrapper for data-dependent screens:

```tsx
<QueryBoundary query={feedQuery} skeleton={<FeedSkeleton />}>
  {(data) => <FeedList items={data} />}
</QueryBoundary>
```

**Rendering large lists:** always `@shopify/flash-list`, never `FlatList`.

**Images:** `expo-image` (supports blurhash placeholders + caching).

## Database (Supabase / PostgreSQL)

Full schema is in `STACK.md §7` and `supabase/migrations/001_initial_schema.sql`. Key conventions:

- All PKs: `uuid DEFAULT gen_random_uuid()`
- All tables have RLS enabled
- `citext` for usernames and slugs (case-insensitive)
- Soft delete via `deleted_at` only on `users` and `reviews`
- `pg_trgm` GIN indexes power book search

Apply migrations via Supabase SQL Editor. After schema changes, regenerate types with `supabase gen types typescript`.

## Testing

- **Unit/integration:** Jest + React Native Testing Library. Test RLS policies against a real Supabase instance — do not mock `supabase`.
- **E2E:** Maestro (not Detox).
- Run a single Jest test: `pnpm jest path/to/test.ts`

## Compliance requirements (store-blocking)

These must ship in MVP or the app will be rejected:

- In-app content reporting with ≤24h internal response
- User blocking with RLS enforcement
- In-app account deletion with 30-day deferred hard-delete (Edge Function `delete-account`)
- Privacy policy URL, granular consent, data export
- Push opt-in shown contextually (not on first launch)
